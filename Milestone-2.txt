Categorical Feature Encoding

Encoding protocol_type and flag
• Applied One-Hot Encoding to convert categories into binary columns.
• Encoder trained on training data only to avoid data leakage.
• Same transformation applied to the test dataset.
• Each category created a separate indicator column.

Encoding service column
• The service feature had a large number of unique values.
• Used frequency encoding instead of one-hot encoding to avoid too many columns.
• Each service value replaced with its occurrence frequency in the training dataset.
• Service values appearing only in test data were assigned value 0.

Cleaning after encoding
• Original columns protocol_type, flag, and service removed after encoding.
• Final encoded dataset shapes printed for verification.

Preparing the Feature Matrix
• Target column attack_class converted to numeric form using LabelEncoder.
• Removed metadata columns not useful for model training such as:
  -label
  -difficulty_level
  -attack_class
  -is_outlier
• Created feature matrices:
  -X_train_fs for training features

• Printed total number of features before performing feature selection.

Removing Highly Correlated Features
• Calculated correlation matrix for all numeric features.
• Extracted upper triangle of matrix to avoid duplicate comparisons.
• Identified features with correlation greater than 0.95.
• Highly correlated features removed because:
Keeping both increases noise without improving prediction.
• Printed:
  -Number of removed features
  -Names of removed features
• Generated a correlation heatmap to confirm reduced redundancy.


Removing Low Variance Features
• Applied VarianceThreshold filtering.
• Features with variance lower than 0.01 removed because:
Such features contribute almost nothing to model learning.
• Filter applied on training data and same columns removed from test dataset.
• Printed:
  -Number of removed columns
  -Remaining feature count.

Feature Scaling
• Applied RobustScaler to normalize numerical values.
Why RobustScaler was used:
• Uses median and interquartile range instead of mean and standard deviation.
• More resistant to extreme outliers.
Scaling procedure:
• Scaler fitted only on training data.
• Same scaling transformation applied to test data.
This prevents data leakage.


Handling Class Imbalance
Problem
• Dataset contained uneven distribution of attack classes.
Example:
• DoS attacks had very large number of samples.
• U2R attacks had very few samples.
This imbalance can cause models to focus mostly on majority classes.


Solution – SMOTE
• Applied SMOTE (Synthetic Minority Oversampling Technique).

How SMOTE works:
• Generates synthetic samples for minority classes.
• Creates new data points between nearby samples instead of copying existing ones.

Implementation:
• SMOTE applied only on training dataset.
• Test dataset left unchanged to represent real unseen data.

Validation:
• Printed class distribution before and after SMOTE.
• Generated comparison plots to show balanced classes.
